# 主题资料库：发现、分类、提炼与接入

资料库应适配每个项目。采用可移动 JSON/CSV/Markdown 起步，不默认要求向量数据库。检索增强可以帮助找片段，但不能把相近文本自动变成可靠结论。

## 1. 先列需要回答的事实问题

将用户的模糊主题拆成：定义、对象差异、可观察行为、结果分类、进入条件、建议依据、变化中的事实。为每个问题列中英文关键词、近义词、排除词、目标人群、时间/地区和需要的材料类型。

例：职业探索分开检索“职业任务/资格/收入”和“兴趣/价值/过程偏好”；关系探索分开检索“关系概念/互动过程”和“干预有效性”；趣味测试以原创设定库为主，无须伪造科学文献。

检索式模板：`[概念] AND [人群] AND (review OR validation OR measurement)`；中文用概念同义词、量表验证、综述、信效度等组合。限制条件按问题加入，不把某个固定年份之后的文章自动当更可靠。

## 2. 哪里找，分别能提供什么

| 需求 | 优先入口 | 必须继续核对 |
|---|---|---|
| 概念、测量与研究 | 论文原文、研究机构、专业学会；Crossref / OpenAlex 等作发现入口 | DOI、题名作者、研究设计、人群、限制、修订撤稿、是否读到全文 |
| 临床健康背景 | PubMed / 正式临床指南发布机构 | 应用边界、更新日期、版权；不拿趣味测评替代诊断 |
| 法规、执照、签证与统计 | 政府、监管部门、统计机构、原始公告 | 生效日期、适用地区、统计口径；旧版不能冒充现行 |
| 书籍和理论 | 出版社、作者、图书馆目录确认版本，再读合法取得的内容 | ISBN、版次、章节/页码、原作者论述与二手解释的区别 |
| 既有量表 | 原论文、量表手册、权利人官方页面 | 授权、中文版本、目标人群、修改限制、原计分和常模 |
| 工作或使用情境 | 用户自述、授权访谈、原始岗位任务材料 | 观察样本和偏差；故事不能当普遍事实 |
| 审美/虚构类趣味测试 | 原创设定、可合法使用的素材 | 标明原创规则，不包装为已验证能力或人格测量 |

没有浏览能力时：先交付检索计划与待核对清单，不编造作者、书名、DOI或结论。获取到摘要仅能提取摘要支持的有限信息；目录和书评不能替代读过相应章节。付费墙不等于材料不可靠，也不授权绕过访问限制。

## 3. 每条资料的记录字段

`sourceId, type, title, authors, year, edition, doi/isbn/url, retrievedAt, access, locator, population, geography, studyDesign, rights, permittedUses, status, reviewAfter, limitations`。

access 使用 `metadata-only / abstract / fulltext / user-provided`；status 区分待查、已读核对、过期、争议、撤回。rights 单独记：可链接、可摘要、可复制、可改编、可商业使用、未知。开放获取不自动等于允许改编问卷或复制整本书。

分类至少有三组标签：**主题**（兴趣/任务等）、**用途**（定义/题目设计/计分/事实建议/UI等）、**状态**（待读/核对/需更新/不采用）。可用 Zotero 的集合、标签与笔记，也可以用相同字段的表格；工具不决定证据质量。

## 4. 从资料提炼可使用的“观点卡”

每张观点卡只写一个可核对主张：claimId、自己的摘要、sourceIds、准确定位、原文支持到哪、适用对象、反例/冲突、允许进入哪些环节。

origin 使用 `published-finding / official-fact / licensed-instrument / user-observation / design-hypothesis / fictional-world`。它们不是一个可简单相加的质量分。对照问题选择证据：官方资格公告适合资格事实，不能证明性格；研究中的群体相关也不能推断某个用户的因果机制。

score 只由明确规则决定。不要把“有 10 篇文献”当作 90% 置信度，也不要把引用次数、样本量或模型语气作为个人匹配度。

## 5. 连接整个产品链路

| 环节 | 资料如何使用 | 典型错误 |
|---|---|---|
| 定义维度 | 说明它是什么、不是哪些相邻概念 | 把兴趣、能力和外部资源混成“天赋” |
| 写题 | 为场景和观察点提供设计理由 | 从一本书摘一句就自称验证量表 |
| 选项 | 记录每个选项观察什么、成本是什么 | 标准答案明显、诱导或所有 A 都加同类分 |
| 计分 | 优先按合法量表原规则，原创模型标明假设 | 修改题目/权重后仍声称保留原量表效度 |
| 匹配结果 | 结果库中的任务、条件、代价与回答信号配对 | 缺学历即给空白报告；或硬说已能从业 |
| 图形 | 先定义指标和分母，再挑合适图形 | 将选择次数改名“人格深度” |
| 建议 | 每个行动来自相应条件和结果差异 | 所有结果共用同一套泛化建议 |
| 更新 | 资料变更后找到受影响的题、分和报告 | 更新了书单却没更新推荐结论 |

最小映射例：`S01 → C01 → construct-a → q1/q4 → scoring-v1 → result-a/reasons → bar → action-a`。原创题也要记录设计依据，允许 `design-hypothesis`，不要求编造文献补齐。

## 6. 审核、矛盾和版本

逐条问：主张与原文相符吗、适用人群是否一致、是否只是相关、是否存在冲突结果、是否有使用许可、是否影响高成本决定。将相互冲突材料并列记录，缩窄结论，不以数量投票决定真伪。

对会变化的事实设 `reviewAfter`（由主题风险决定，例如政策发布后/每季度），到期标记需复核。对更正、撤稿和新版手册，记录替代关系并追踪受影响的产品ID。保留来源快照或定位信息，但不在开源包放未授权书籍全文、私有访谈或用户答案。

交付内部四项：检索日志、来源表、观点卡、映射表。消费者主报告集中展示个人结论；内部研究状态不变成“你未完成自评”等无用交付。必要署名、授权说明仍需按条款保留。

## 已核对的方法工具说明（2026-11-01）

- [Crossref 官方元数据 API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)：用于发现并核对学术记录；不等于取得论文全文或证明某条结论。
- [OpenAlex 官方帮助](https://help.openalex.org/)：文献发现入口；具体访问能力以当前文档为准。
- [Zotero 官方分类方法](https://www.zotero.org/support/collections_and_tags) 与 [笔记](https://www.zotero.org/support/notes)：可组织来源及观点定位，不能自动完成证据评估。

# UI、情境与报告结构

## 先定信息层级，再选风格

确定用户最先需要的答案：主要方向 → 个性化解释 → 条件冲突 → 相邻选择 → 入门建议 → 按需展开细节。内部检索与计分审计另存；必要的指标说明保持短小可读。

`assets/design-library.json` 提供 8 套色彩角色、10 种问答交互、6 种结果布局、8 种情境结构。它们是起点，不替代品牌要求。每次设计先说明主题、人群、情境、主结论、数据类型和报告章节，再选合适模板。

## 配色规则

使用角色而非随意挑色：背景、卡片、主字、次字、主操作、主操作文字、边框、重点、图表系列、焦点、错误。主操作与正文对比按实际相邻组合检查。正文通常需至少 4.5:1，大字至少 3:1；本项目将可读文字对统一按 4.5:1 检查。颜色不能是唯一含义。

8 套预设：蓝橙编辑、米白森林、暖粉可可、奶油紫、海洋青、暖黄石墨、暗夜薄荷、极简黑白。图形的序列颜色不等于文本颜色；彩色装饰不自动适合作为白字按钮。

## 问答框与选项

- 默认单选：整卡可点，字母/序号+文字；选中有边框、选中标记和短反馈，延迟约 180–300ms 后前进，防连点；上一题可修改。
- 多选：标明可选数量，用户确认后前进，不能每点一个就跳题。
- Likert：每档有具体含义，手机纵向或分组；“不适用/不知道”不计成中立。
- 场景取舍：让成本和条件对称，不把某个选项写得明显高尚。两极端点不能掩盖“都不适合”。
- 滑块仅用于有意义的连续范围；默认位置不是已回答，必须有键盘与数值替代。排名要有上下移动按钮，拖拽不能是唯一方式。
- 图片/emoji 选项要有文字与可访问名称；图片风格、人物吸引力和表情强度不应替答案诱导。不要用开心脸表示“正确”、哭脸表示“错误”。

包含 normal / hover / selected / focus / disabled / error 六态；错误需告诉用户如何继续。推荐触控高度至少 44px（产品目标，强于 WCAG 24px 的基础门槛）。卡片留足间隔，主按钮在窄屏不遮住内容，支持减少动画偏好。

## 场景化题目与讲解

可选择：一天的日程、同一任务的两种做法、一次被拒绝后、预算不足时、长期重复任务、计划被打断、他人期待冲突、三阶段未来路径。

每个情境写清触发、目标、资源、代价、选择和后果。只说明与所测维度有关的细节。避免用高消费旅行、精英办公室等单一场景排除其他人；提供等价的日常版本。不能仅凭一个情境推断用户“真正潜意识”或终身天赋。

呈现可以是分镜、对话泡泡、任务卡、桌面/日历、预算筹码、流程分叉、前后对照；可视化是降低理解成本，不是新增分数证据。分支变化时清除不再适用的后续答案。

## 六种报告布局

1. **结论优先**：一句主结论、两到三项理由、风险、行动。适合首次探索。
2. **主线/副线**：主线、独立副线、各自匹配理由、交叉成本。适合职业/副业。
3. **比较决策**：二到四个候选，矩阵、冲突和进入条件。适合路径比较。
4. **多维画像**：少量可解释维度，条形/雷达+叙述，避免标签堆积。
5. **场景剧本**：用户情境→选择→可能代价→可改变条件，适合互动模式探索。
6. **阶段路线**：现在/准备期/后续选择，时间线或甘特+资源约束。预测和计划需标明。

预算、资料、资格、详细路线放到用户选择结果后按需展开；不让结果页变成重新填表。每区都有一个决策目的，避免同一句泛话填满各区。保存版必须包含同样结论。

## Emoji 和小图标

给类别或导航提供轻量锚点，例如 🧭方向、🛠行动、🧩组合；总量克制，每节最多一个。装饰 emoji 可用 `aria-hidden=true`，有含义的图标配文字。注意系统字体外观差异，不把 emoji 作为唯一图例或按钮名称。自绘 SVG 图标需要一致线宽、尺寸和文字替代。
